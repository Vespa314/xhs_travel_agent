一直以来去新的城市旅游，不管是国内国外，做攻略都是一件很耗时的事情，不过虽然耗时，也基本是公式化的操作：
1. 大量翻阅小红书的帖子（基本上现在只参考小红书了）：包括但不限于找美食，景点买票攻略，找可能的踩雷点
2. 把相关的景点，美食店位置标记在地图软件上
3. 根据关键景点的位置定好住宿的大致位置
4. 根据上述结果，安排行程，订票，订酒店

在AI agent时代，我一直都感觉除了最后付钱找酒店那一步，很多前置的工作都可以让AI帮忙解决，近期我就沉淀出了一套方案；

依赖主要就是：
- Claude Code(或者Openclaw这些都行)
- [OpenCLI](https://github.com/jackwener/opencli)：为了让AI自行翻阅小红书
- 高德地图skill：比如[Web Service API](https://github.com/kaichen/amap-skill)，官方的[JSAPI](https://github.com/AMap-Web/amap-skills)和[高德地图综合服务Skill](https://github.com/AMap-Web/amap-lbs-skill)，当然使用这些你需要申请相关的api key，免费的

接下来把自己一直以来制作攻略的流程描述成需求，提交给AI即可，具体可以查看[github仓库](https://github.com/Vespa314/xhs_travel_agent)，一些关键点包括：
- 攻略
    - 必须查看多个高赞的帖子，必要时下载图片后理解里面的内容，不要看过期笔记
    - 注意关注踩雷的相关笔记
    - 笔记原贴链接需要放在攻略文档里面
    - 攻略要图文并茂
- 地图：
    - 标记好每天的景点和路线，计算路线耗时
    - 美食和景点，住宿区域备注信息需要提示在POI点上，并附带笔记链接

当然这个也可以整个封装成一个skill，不过我是专门建了一个制作旅游攻略的目录，让AI在里面制作各种攻略（并沉淀一些经验），还可以互相参考其他已有攻略的经验做法，就没有单独搞个skill了；（比如第一次做地图的话会有很多细节需要修改，但是一旦做好了，沉淀好的功能和代码给第二次攻略做参考，那么地图部分基本就不用费什么心思去优化了）

当我拿到这个结果，就可以去对照着笔记来挑选我心仪的美食和景点，并且对整个路线、耗时、地理位置都有了一个大致的认知结果了。

AI虽然制作这么一份东西可能要半个小时到1个小时，但是全程不需要我干预，而且由于质量基本上和我自己做的差不多，所以现在我还挺喜欢让AI去做各种各样的城市的攻略来给我阅读。
